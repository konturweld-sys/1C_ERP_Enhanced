# Расширение 1С:ERP «Интеграция» — PDM → RabbitMQ → ERP

## Назначение

Исходная выгрузка существующего расширения **«Интеграция»** для импорта в 1С:EDT и последующей проверки на отдельной тестовой информационной базе ERP.

Ветка: `fix/pdm-erp-rabbitmq-recovery`  
База сравнения: `erp_enhanced_actual`

Это исходники расширения, а не собранный файл `.cfe`. Компиляция и выгрузка `.cfe` должны выполняться в 1С:EDT с установленной целевой платформой.

## Состав

- Общие модули:
  - `ЕРП_ПриемИнтеграции`
  - `ЕРП_ВалидацияКонтракта`
  - `ЕРП_СопоставлениеНоменклатуры`
  - `ЕРП_ИнтеграцияRabbitMQ`
  - `ЕРП_ЖурналИнтеграции`
- Регистры сведений:
  - `ЕРП_НастройкиИнтеграцииRabbitMQ`
  - `ЕРП_БлокировкаПриемаRabbitMQ`
- Обработка `ЕРП_НастройкаИнтеграцииRabbitMQ` с управляемой формой.
- Регламентное задание `ЕРП_ПриемНоменклатурыИзPDM`.
- Общий макет внешней компоненты `PinkRabbitMQ` (включая бинарный шаблон).
- Служебная роль `Интеграция_ОсновнаяРоль`.

Новые регистры и объекты для восстановления не добавлялись. Основная конфигурация ERP не изменяется.

## Изменения в этой ветке

1. Исправлен способ подключения нативной компоненты через `ОбщийМакет.PinkRabbitMQ`, алиас `BITERP`, объект `AddIn.BITERP.PinkRabbitMQ`.
2. Добавлено сохранение настроек в существующий регистр.
3. Форма настроек теперь может открыться до первичного заполнения регистра: при отсутствии записи поля открываются пустыми.
4. Добавлена проверка допустимого диапазона порта и обязательных параметров подключения.
5. Проверяется связность `ПутьРодителей`: корневая группа, последовательность родителей и совпадение последней группы с `Родитель_UUID`.
6. Группы и элементы формируют родительскую иерархию по одному и тому же пути PDM.
7. При обновлении существующей группы синхронизируется родитель, включая перевод в корень.
8. У общих модулей приёма и валидации включён признак «Вызов сервера».
9. Удалена отдельная диагностическая функция проверки записи журнала.

PDM-отправитель, формат JSON, exchange, очереди и routing keys этой веткой не изменяются.

## Контракт и фактический объём обработки

Входящая очередь: `pdm_to_erp_nomenclature`  
Exchange: `1c_integration`  
Очередь статусов: `erp_to_pdm_statuses`  
Routing key статуса: `status_key`

Текущая обработка создаёт/обновляет группы и элементы справочника `Номенклатура` по UUID PDM, наименованию, артикулу и родительской иерархии. Локальный код ERP не перезаписывается.

Поля типа и вида номенклатуры, единицы измерения, характеристики и спецификация проверяются валидатором входного контракта, но в текущей версии не переносятся в соответствующие объекты ERP. Это осознанная граница первой версии для первичной проверки; правила их сопоставления нужно согласовать отдельно до расширения бизнес-логики.

## Подготовка среды

1. Использовать отдельную тестовую информационную базу ERP и резервную копию перед импортом.
2. Открыть проект расширения в 1С:EDT как исходники конфигурации из файловой системы.
3. Убедиться, что целевая платформа соответствует совместимости расширения `8.3.27`.
4. Проверить наличие и разрядность нативной компоненты PinkRabbitMQ на сервере 1С; бинарный шаблон входит в исходную выгрузку.
5. У сервисного пользователя кластера должны быть права на чтение/запись справочника `Номенклатура`, работу с регистрами расширения и выполнение регламентных заданий. В текущей выгрузке роль `Интеграция_ОсновнаяРоль` создана без объектных прав; для первого запуска используйте тестового пользователя с уже подтверждёнными необходимыми правами либо предварительно настройте роль в EDT.
6. Серверный процесс 1С должен иметь право создавать/дополнять файл журнала `D:\\1C Log\\ERP_Nomenclature_Integration.log`.
7. В обработке `ЕРП_НастройкаИнтеграцииRabbitMQ` заполнить адрес, порт, пользователя, пароль и vhost фактического RabbitMQ.
8. Проверить наличие exchange `1c_integration` и корректные bindings очередей на стороне RabbitMQ. Расширение не создаёт и не перенастраивает очереди автоматически.

## Ограничения статуса

- Исходники проверены статически; компиляция в EDT не выполнялась.
- Тесты не запускались.
- Подключение к реальному RabbitMQ и двум базам 1С не проверялось.
- В рабочую базу ERP изменения не переносились.
- Файл `.cfe` не собран.
- Перед рабочим использованием требуется проверить права роли, расписание регламентного задания и фактические свойства объектов целевой ERP в EDT.

Сначала импортируйте исходники в тестовый проект EDT, устраните возможные расхождения с фактической конфигурацией ERP и только затем создавайте `.cfe` для загрузки в тестовую базу.
